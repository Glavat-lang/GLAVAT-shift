# GLAVAT РАСПИСАНИЕ

Веб-приложение для управления сменами команды караоке «Баритон».

**Стек:** React 18, Vite, Supabase Auth, PostgreSQL, Supabase Realtime, GitHub Pages.

## Возможности

- Вход сотрудников по одноразовой ссылке на email.
- Регистрация новых сотрудников только по приглашению владельца или администратора.
- Роли: владелец, администратор, сотрудник.
- Общий недельный и месячный календарь, список смен и фильтр по сотрудникам.
- Создание, редактирование, копирование, публикация и удаление смен.
- Проверка пересечений смен, включая ночные смены через полночь.
- Заявки на выходной, замену, обмен сменами и изменение времени.
- Одобрение и отклонение заявок с комментарием.
- Подсчёт часов и количества смен за выбранную неделю или месяц.
- История действий руководителей.
- Внутренние уведомления о назначении, изменении, передаче и отмене смен, а также о решении по заявке.
- Обновление расписания в реальном времени.
- Адаптация под телефон и установка на главный экран как PWA.

## Локальный запуск

```bash
npm install
cp .env.example .env
npm run dev
```

В `.env` используются:

- `VITE_SUPABASE_URL`
- `VITE_SUPABASE_ANON_KEY` — публичный publishable/anon key.

Service-role и другие секретные ключи нельзя помещать во frontend, GitHub или файл `.env.example`.

## База данных и безопасность

Полная последовательность SQL-миграций хранится в `supabase/migrations/`. Она включает таблицы, индексы, триггеры, функции, роли и политики Row Level Security.

RLS включён на всех прикладных таблицах. Проверки прав выполняются на стороне PostgreSQL, а не только в интерфейсе. Публичный клиент использует только publishable key.

## Публикация

GitHub Actions автоматически собирает приложение и публикует каталог `dist` в GitHub Pages при изменениях в ветке `main`.

Для корректной работы авторизации в Supabase → Authentication → URL Configuration должны быть заданы:

- **Site URL:** `https://glavat-lang.github.io/GLAVAT-shift/`
- **Redirect URLs:** `https://glavat-lang.github.io/GLAVAT-shift/`

## Обязательная настройка email перед приглашением команды

Встроенный почтовый сервер Supabase предназначен для тестирования: он отправляет письма только на адреса участников организации Supabase и имеет строгие лимиты. Для отправки magic link обычным сотрудникам необходимо подключить SMTP-провайдера в Supabase → Authentication → SMTP Settings.

SMTP-пароль хранится только в настройках Supabase. Его нельзя коммитить в репозиторий.

## Границы текущей версии

- Уведомления о расписании отображаются внутри приложения; push-уведомления и отдельная рассылка о сменах по email не включены.
- Доставка magic link обычным сотрудникам зависит от настройки SMTP, описанной выше.
- Перед массовым запуском следует проверить вход с отдельной учётной записью сотрудника и полный цикл приглашения на реальном почтовом адресе.
